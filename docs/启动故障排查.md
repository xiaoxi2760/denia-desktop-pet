# 娅娅桌宠 · 启动故障排查

> 这份文档记录 2026-10-15 那次"双击没反应"的完整排查过程。
> 结论先写在最前面，别被后面的过程带偏。

---

## 结论（一句话）

**如果你是在 DSH（DeepSeek Harness）的工作区目录里放桌宠，它一定打不开。**
把项目目录挪到 DSH 工作区**之外**就能正常启动，**不需要任何启动参数**。

---

## 一、症状

双击 `启动娅娅.cmd` 后进程立刻消失，没有任何窗口、没有托盘图标、没有任何报错。
在命令行里手动跑，能看到退出码：

```
-2147483645   （十进制有符号）
= 0x80000003  EXCEPTION_BREAKPOINT
```

---

## 二、根因

**不是桌宠的代码问题，不是 Electron 装坏了，也不是中文路径。是 DSH 沙箱打在工作区上的权限标记。**

DSH 为了做文件访问隔离，会给工作区目录链（从工作区根一路往下）写入 `S-1-4-*` 能力 SID 授权条目。
Electron 在启动早期要初始化 Chromium 的进程沙箱（受限 token + job object），
**这套机制在带能力 SID 的目录上初始化失败 → 命中 DCHECK → `__debugbreak()` → 0x80000003**。
进程在创建任何窗口之前就死了，所以看起来"双击没反应"。

---

## 三、判据（对照实验，2026-10-15 实测）

**决定性判据**：拿同一个 `electron.exe` 在两个位置跑一条**什么都不做**的命令：

```
electron.exe --version
```

| 项目 | `D:\denia\娅娅桌宠-v1.0\...`（工作区外） | `D:\zhuochong\denia\...`（工作区内） |
|---|:--:|:--:|
| DSH 能力 SID 条目数 | **0** | **2** |
| `electron.exe --version` | ✅ 输出 `v43.7.11`，exit 0 | 💥 exit `-2147483645` |
| 直接启动桌宠 | ✅ 正常起来 | 💥 秒退 |
| 二进制 SHA256 | `E1D8F472E00E87899B05EFEBF8D216FD01D82B5BD40B4A1FF2F017EB06D2BD2F` | **同一个** |

两边 `electron.exe` **逐字节相同**，且与官方原版下载一致（已用 npm 重新下载 43.7.11 校验过 SHA256）。
**字节没问题，是位置有问题。**

### 已经排除掉的假设

| 曾经的假设 | 怎么排除的 |
|---|---|
| 项目路径含中文 | 纯 ASCII 路径 `D:\zhuochong\denia` 同样崩 |
| 项目代码有 bug | 8 行最小 Electron 应用用同一个二进制，同样崩 |
| Electron 安装损坏 | 与官方原版 SHA256 逐字节一致，dist 75 个文件齐全 |
| GPU / ANGLE 相关 | `--disable-gpu`、`--in-process-gpu`、`--use-angle=swiftshader`、`--disable-gpu-compositing`、`--disable-software-rasterizer` 五种全崩 |
| 单实例锁 / userData 权限 | `%APPDATA%\denia-desktop` 给当前用户 FullControl，写入测试通过 |
| Electron 版本回归 | 43.7.11 和最新的 44.7.2 **都崩**，都只有加 `--no-sandbox` 才能起 |

---

## 四、不要用 `--no-sandbox` 修这个问题

加了 `--no-sandbox` 确实能起来（已实测），**但这是错误做法**：

1. **它是安全降级**。关掉 Chromium 沙箱等于关掉渲染进程的进程隔离，
   她加载的 MMD 模型 / 贴图 / 动作用的是第三方资源，等于把渲染进程的风险敞开来。
2. **它掩盖真因**。真正的毛病在 DH 沙箱那边，加了 flag 之后问题"消失"了，
   于是没人会去修，下次换一个 Electron 应用（QQ、Discord、VSCode、任何 Chromium 程序）又踩一次。
3. **它治不了别人**。`--no-sandbox` 是 Chromium 的全局开关，对工作区里**所有** Electron/Chromium 程序都有用，
   也就是说一旦发现这招"好使"，就会有人到处加 —— 应该反过来：把程序挪出工作区。

**正确做法**：项目放到 DSH 工作区之外（例如 `D:\denia\娅娅桌宠-v1.0`），不加任何参数启动。

---

## 五、怎么确认你在不在工作区里

看项目所在目录链上有没有 DSH 的能力 SID 条目：

```powershell
(Get-Acl '<项目路径>\node_modules\electron\dist').Access |
  Where-Object { $_.IdentityReference -like 'S-1-4-*' } |
  Measure-Object | Select-Object -Expand Count
```

- 输出 `0` → 干净，正常启动
- 输出大于 `0` → 在工作区里，**把项目挪出去**

DSH 工作区根目录可以从会话信息里看到（形如 `D:\zhuochong`），
**工作区根及其所有子目录**都会被打上标记。

## 六、其他启动故障对照表

| 现象 | 原因 / 处理 |
|---|---|
| 双击 cmd 一闪而过，看不到任何提示 | 先在命令行里手动跑 `启动娅娅.cmd` 看报错；退出码 `-2147483645` 就是本文说的 DSH 问题 |
| 命令行里报 `'xxx' 不是内部或外部命令` | `.cmd` 脚本里混进了非 ASCII 字符（尤其是破折号 `—`）。cmd 按 GBK 解析会被切碎。`.cmd` 内容必须 100% 纯 ASCII、无 BOM |
| 进程活着但没有窗口 | 托盘图标里可能被点了"藏起来"。右键托盘 → 出来吧 |
| 白屏 / 模型不显示 | MMD 模型 + 物理引擎首次加载慢，等几秒。还不行看杀毒软件有没有拦 `tools\foreground.exe` |
| 联机模式提示"连不上她" | 后端没跑 / 端口不对 / `consoleToken` 不一致 / SSH 主机没配免密登录 |
| 独立模式提示"还没配 API Key" | 托盘 → 独立 AI 设置，填 API 地址 / Key / 模型 |
| 启动日志里有 `process_singleton_win.cc ... Error code: 5` | 沙箱挡住了对 `%APPDATA%\denia-desktop` 的写入。移出工作区即可消除 |
