## 0. 前置：客户端得先能起来

本文档讲的是接口契约，但**在你按下面的契约写后端之前，先确认桌宠客户端本身能正常启动**——
否则没法端到端联调。

> ⚠️ **桌宠项目不要放在 DSH（DeepSeek Harness）的工作区目录里。**
> DSH 沙箱给工作区写的权限标记会让 Chromium 的进程沙箱初始化失败，
> 进程以 `-2147483645`（`0x80000003`）在开窗前秒退，表现为"双击没反应"。
> 把项目放在工作区之外即可正常启动，**不需要任何启动参数，也不要加 `--no-sandbox`**。
> 证据链与诊断方法见 **[`启动故障排查.md`](启动故障排查.md)**。

### 后端实现者需要先定的一件事

`config.local.json` 里 `sshHost` 的默认值是字符串 `'pc'`，
而且代码是 `String(x || 'pc')` —— **填 `""` 会回落到 `'pc'`，不是直连**。
所以：

- 后端就在**本机** → 必须显式改代码或确认逻辑，不能靠留空
- 后端在**远端** → 需要目标主机配好 SSH 免密登录，否则隧道永远拉不起来

详见 [§2.1 配置接口](#21-桥接段模式-a)。

## 5. 桥接 HTTP 接口（模式 A：后端需要实现的）

通用约定：

* Base：`http://127.0.0.1:{tunnelLocalPort}`（默认 `http://127.0.0.1:13100`）
* 鉴权：**每个请求**都带 `x-console-token: <consoleToken>`（为空则发空串）
* 隧道：探活失败且 `consoleToken` 非空时 `spawn ssh -N -L <local>:<bridge> <host> -o BatchMode=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=20`
* 拉起隧道后**轮询 12 次**，每次 `sleep 400ms` + `pingBridge()`（单次上限 1200ms）
  ⇒ 快速失败 ≈4.8s；连接被拒/挂起时最坏 ≈19s

### 5.1 `GET /api/status` — 探活（必需）

* 调用点：`pingBridge()`（1200ms 超时）、`bridgeStatus`（20s 超时）
* **只要 `res.ok`**，body 完全不解析
* `bridgeStatus` 额外读 `{mode, role, dshReady}` 三个字段透传给渲染层
* 调用时机：**没有独立定时器**。由 `pet:recent`（渲染层每 4s 轮询一次）、`pet:say`、`pet:watch-preset`、
  启动后 800ms 的 `bridgeStatus` 顺带触发

### 5.2 `POST /api/socialV2/pet-chat` — 说话（必需）

```http
POST /api/socialV2/pet-chat
x-console-token: <token>
content-type: application/json

{"key":"private:<ownerQQ>","text":"在干嘛"}
```

* 客户端硬超时 **90000ms**；串行化（渲染层一次只发一条，队列串行）
* 请求体**只有 `key` 和 `text` 两个字段** —— 旧文档里的 `image` / `timeoutMs` **桌宠从不发送**
* 看屏幕时桌宠只发文本「看看屏幕」，**截图由后端自己取**（`main.js:710` 注释明确）
* 响应透传给渲染层，渲染层认这些字段：

| 字段 | 必填 | 用法 |
|---|---|---|
| `ok` | 是 | `false` ⇒ 气泡显示 `接不上她：<error>` |
| `reply` | 是 | 空串 ⇒ 显示「（她这次没接话）」；非空 ⇒ 入语音队列并念出来 |
| `recent[]` | ⚠️ **建议恒返回 `[]`** | 格式是 `{ts\|time, self\|isSelf, text}`，但**填非空会静默吞掉主动冒泡**，见下方警告 |
| `error` | 否 | 错误文案 |
| 其余 | 否 | 透传不解析（如 `waitedMs`、`impl`） |

* 非 JSON 响应会在 `res.json()` 处抛错，被主进程包成 `{ok:false,error:'…'}`

> #### 🔴 警告：`pet-chat` 的 `recent` 请恒返回 `[]`
>
> `app/main.js:1299-1310` 拿到 `pet-chat` 的响应后会做两件事：
>
> ```js
> const newest = recent.reduce((m, r) => Math.max(m, Number(r.ts ?? r.time) || 0), lastSeenTs);
> lastSeenTs = newest;                                    // ← 高水位线，直接覆盖
> ```
>
> `lastSeenTs` 是一个**高水位**，不是逐条标记。而 §5.3 的主动冒泡取消息条件是
> **`m.ts > lastSeenTs && m.self`**。
>
> 所以：`recent` 里只要出现任何一条 `ts` 大于"某条还没被念出来的主动消息"的条目，
> `lastSeenTs` 就会跳到它之上，**那条主动消息从此永远不会再被念，而且不报任何错**。
>
> ⇒ 后端实现建议：
> - `recent` **恒返回 `[]`**；
> - **本轮的 `reply` 不要同时写进消息表**——它已经被 `reply` 字段直接念了一遍，
>   再写进 `/recent` 会造成重复；
> - 只有**真正主动**（非本轮回复产生的）消息才留在 `/recent` 里等轮询取走。
>
> ⚠️ 旧文档 `桌宠对接接口文档.md` §2 在响应示例里带了 `recent` 数组，**照着实现会踩这个坑**。

### 5.3 `GET /api/socialV2/recent?key=…&limit=20` — 主动冒泡（强烈建议）

* 客户端超时 **20000ms**；渲染层 **每 4000ms** 调一次
* 响应：`{"ok":true,"messages":[{"ts":<ms>,"self":true,"text":"…"}]}`
* 渲染层行为（严格照抄即可不出错）：
  1. 归一化：`ts = m.ts ?? m.time`，`self = m.self ?? m.isSelf`
  2. 丢弃 `ts<=0` 或空文本的条目
  3. **第一轮只记水位**（`lastSeenTs = newest`），不补历史
  4. 之后取 `m.ts > lastSeenTs && m.self`，**逐条**入语音队列（不叠在一起）
  5. `ts` 水位还会写进 `speech.spokenTs`，配合 `pet-chat` 的 `recent` 做**跨通道去重**
     （同一句先被轮询念过、后被发送路径拿到时不会被吃掉）
* ⇒ **`ts` 必须严格递增且唯一，用毫秒**

### 5.4 `POST /api/socialV2/screen-permission` — 看屏幕许可（可选）

```http
POST /api/socialV2/screen-permission
{"watch":true,"minutes":30,
 "minGapMs":25000,"maxGapMs":45000,"changeThreshold":8,
 "sameWindowCooldownMs":420000,"speakMinGapMs":240000,
 "quietAfterOwnerMs":120000,"maxInjectsPerHour":6}
```

两档预设（`main.cjs:633-636`）：

| mode | minGapMs | maxGapMs | changeThreshold | sameWindowCooldownMs | speakMinGapMs | quietAfterOwnerMs | maxInjectsPerHour |
|---|---:|---:|---:|---:|---:|---:|---:|
| `quiet` | 25000 | 45000 | 8 | 420000 | 240000 | 120000 | 6 |
| `chatty` | 5000 | 9000 | 1.5 | 30000 | 20000 | 5000 | 60 |

* 其它 mode 值一律按 `quiet` 处理
* **只会发 `watch:true`**，请求体不含截图
* 超时 90s；失败静默忽略，沿用默认档

### 5.5 `POST /api/socialV2/voice-preview` — 语音合成（可选）

⚠️ **与旧文档不符**：桌宠**不接受二进制音频**。代码要求 JSON：

```json
{ "ok": true, "file": "/远端绝对路径/voice/xxx.mp3", "ms": 1234, "kb": 88, "label": "GPT-SoVITS" }
```

流程：`POST {text}`（超时 **180000ms**）→ 取 `file` → `scp -q -o BatchMode=yes <sshHost>:<file> <本地 voice/>`（超时 30s）
→ 返回 `denia://voice/<basename>`，渲染层 `fetch` 后用 `Audio` 播放。
`file` 缺失 / `ok:false` ⇒ `{ok:false,error}`。同名文件按 basename 覆盖。

> #### 🔴 警告：联机模式**没有**系统 TTS 兜底
>
> `petVoice()`（`main.cjs:1303-1327`）的结构是：
>
> ```js
> if (STANDALONE.enabled) {
>   ... engine === 'sapi' ? synthSapi(...) : synthVoiceApi(...)   // ← 系统 TTS 只在这条分支里
>   return ...
> }
> return petVoiceViaBridge(clean);                                // ← 联机模式直接走这里，没有兜底
> ```
>
> `synthSapi()`（Windows 本地 `System.Speech`，零配置、免费、中文可用）
> **只在独立模式分支里被调用**。联机模式下 `petVoiceViaBridge` 一旦失败
> （隧道不通 / `voice-preview` 返回 `ok:false` / `scp` 失败），直接返回 `{ok:false,error}`，
> **不会再退回系统语音**。
>
> ⇒ 后果：**联机模式的后端如果不实现 `voice-preview`，她就只有气泡、永远没有声音**。
>
> 两条出路，二选一：
> 1. **后端实现 `voice-preview`**（注意必须返回 JSON `{ok,file}` + 可 `scp` 的远端绝对路径，
>    且 `sshHost` 要能免密登录——代码用的是 `BatchMode=yes`，没免密就秒退）；
> 2. **改 `main.cjs` 约 10 行**，把 `petVoiceViaBridge` 的失败分支接到已有的 `synthSapi()`，
>    这样联机模式失败时自动退回 Windows 系统语音（最省事拿到中文女声）。

## 6. 独立模式外部 HTTP 接口（模式 B）

### 6.1 对话：`POST {baseUrl}/chat/completions`

请求（`main.cjs:244-256`）：

```json
{ "model":"…", "messages":[{"role":"system","content":"<persona>"}, {"role":"user","content":"…"}],
  "max_tokens":2048, "stream":false }
```

* 头：`authorization: Bearer <apiKey>`
* 超时 **120000ms**（AbortController）
* 兼容 `200 + base_resp.status_code != 0` 的老式平台（如 MiniMax），报 `接口返回错误：…`
* 404 ⇒ 提示「检查接口地址是否只填到 `/v1` 结尾」；401/403 ⇒ 提示检查 Key
* 历史：内存环形，上限 `historyLimit`（默认 40 条 user+assistant 合计），**重启即失忆**

### 6.2 看屏幕（视觉）

| 触发 | 行为 |
|---|---|
| 聊天文本**精确等于** `看看屏幕` | `desktopCapturer` 抓全屏 JPEG（宽 1280 / q60）作为 `image_url` 塞进 user 消息 |
| 聊天文本**精确等于** `陪我看会儿` | 启动本地陪看循环（默认 quiet） |
| 聊天文本**精确等于** `别看了` | 停止本地陪看 |
| 陪看循环 | 每 `intervalMs` 抓 320px 缩略图与上帧比采样差异；`diff ≥ diffPercent` 且距上次开口 ≥ `minGapMs` 且每小时未超 `maxPerHour` → 抓 960px JPEG(q55) 问视觉模型（`max_tokens 220`），非空非省略号则入 `STANDALONE_INBOX` |

| mode | intervalMs | diffPercent | minGapMs | maxPerHour |
|---|---:|---:|---:|---:|
| `quiet` | 60000 | 6 | 240000 | 6 |
| `chatty` | 30000 | 2.5 | 60000 | 30 |

启动陪看后 **6 秒**强制先瞄一眼；`force` 一次跳过差异门槛（仅首眼 / 自检用）。
视觉单次请求**不进对话历史**（`standaloneVisionOnce` 独立构造 messages），超时 120s。

### 6.3 主动消息队列（替代 `/recent`）

`STANDALONE_INBOX` 是主进程内存数组；`pet:recent` 每次 `splice(0,20)` 取走，
映射成 `{ts, text, self:true}` —— 与桥接模式返回结构**完全一致**，渲染层无感知。

## 7. TTS 引擎的外部 HTTP 契约

统一入口 `synthVoiceApi(text)`（`main.cjs:1093`），总超时 **150000ms**；输入截断 500 字符。
结果 `{buf, ext, engine}`，落盘 `voice/` 后返回 `denia://voice/<file>`（缓存只保留最新 40 个音频文件）。

| engine | 端点 | 鉴权 | 请求要点 | 响应 |
|---|---|---|---|---|
| `sapi` | 本机 PowerShell `System.Speech` | — | 环境变量传 `PET_TEXT/PET_OUT/PET_VOICE`，30s 超时 | 本地 `.wav` |
| `sovits` | `{sovitsUrl}/set_gpt_weights`、`/set_sovits_weights`、`/tts` | 无 | 权重变更时才加载（`sovitsLoadedWeights` 去重）；`text_lang` 含假名自动判 `ja`；`text_split_method:'cut5'`，`media_type:'wav'` | 二进制 wav，<2000B 判失败 |
| `fish` | `{fishUrl}/v1/tts` | `Bearer <fishKey>` + 头 `model: s1` | `{text,format:'mp3',mp3_bitrate:128,chunk_length:200,normalize:true,reference_id}` | 二进制 mp3，<1000B 判失败 |
| `openai` | `{oaiUrl}/audio/speech` | `Bearer <oaiKey>` | `{model,input:text,voice,response_format:'mp3'}` | 二进制 mp3 |
| `volcano` | `{volcanoUrl}` 默认 `https://openspeech.bytedance.com/api/v1/tts` | `Bearer;<token>` | `{app:{appid,token,cluster},user:{uid:'denia-desktop'},audio:{voice_type,encoding:'mp3',speed_ratio},request:{reqid:UUID,text,operation:'query'}}` | JSON，`code===3000` 时 `data` 为 base64 |
| `volcano3` | `{volcano3Url}` 默认 `…/api/v3/tts/unidirectional/sse` | `X-Api-Key` 或 `X-Api-App-Id`+`X-Api-Access-Key`，另带 `X-Api-Resource-Id` / `X-Api-Request-Id` | `{user,req_params:{text,speaker,audio_params:{format:'mp3',sample_rate:24000,speech_rate}}}` | **SSE**，逐行 `data: {"code":0,"data":"<base64 chunk>"}`，`20000000` 视为正常 |
| `minimax` | `{minimaxUrl}` 默认 `https://api.minimax.cn/v1/t2a_v2` | `Bearer <minimaxKey>` | `{model,text,stream:false,voice_setting:{voice_id,speed,vol:1,pitch:0},audio_setting:{sample_rate:32000,bitrate:128000,format:'mp3',channel:1}}` | JSON `data.audio` 为 **hex** |

连接类错误（ECONNREFUSED / fetch failed / aborted）统一包装成「连不上语音服务（<engine>）：…」。

## 8. ASR（语音输入）契约

`pet:asr(wavBytes)` —— 渲染层先用 `OfflineAudioContext` 重采样成 **16kHz / 单声道 / 16bit PCM WAV** 再传。

**主通道（常驻服务）**：`whisper-server.exe` → 轮询 `GET http://127.0.0.1:<port>/` 判就绪（25s 期限，`cwd` = 模型目录），
启动参数 `-m <basename> -l zh -t 6 -nt --prompt <prompt> --port <port>`；就绪有效期 12 小时。
转写：`POST /inference`（multipart，`file`/`language=zh`/`response_format=json`/`prompt`，60s 超时）。

**兜底通道**：`whisper-cli.exe -m <basename> -f <tmp.wav> -l zh -t 6 -np -nt -otxt -of <outBase> --prompt <prompt>`（90s 超时）。
连崩 2 次 ⇒ 冷却 10 分钟并尝试拉起常驻服务，期间直接返回「耳朵正在重启…过十秒再说一遍」。

**幻觉过滤**（两条通道统一，`isAsrGarbage`）：提示词回声（`以下是普通话的句子|请用简体中文转写…`）、
常见视频幻觉词（`谢谢观看|字幕由|请点赞订阅…`）、不认识的单字、纯标点 ⇒ 当作「没听清」，返回空串。

**并发**：同一时刻只转写 1 条；排队最多留 1 条（新的顶掉旧的），避免免提连说丢句。
临时文件在 `%TEMP%\denia-asr\in-<ts>.wav` / `.txt`，用完即删。

## 12. 行为契约速查（给后端实现者）

1. **最小可用 = `/api/status` + `/api/socialV2/pet-chat`**。实现这两个就能聊天。
2. **她会不会主动找你 = `/api/socialV2/recent`**。`ts` 必须毫秒、严格递增、唯一。
3. **`reply: ""` 是正常的**（她选择沉默），桌宠显示「（她这次没接话）」，**不是故障**。
4. **`pet-chat` 必须在 90 秒内返回**，哪怕超时也要返回 `"reply": ""`。
5. **未知字段一律忽略**；缺 `text` 或空 → `400 {"ok":false,"error":"…"}`。
6. `key` 固定为 `private:<ownerQQ>`，当作会话 id 做上下文记忆。
7. **不要给同一句回复两个通道都念**：`pet-chat.reply` 与 `/recent` 里的同一条会被桌宠用 `ts` 水位去重，但 `ts` 必须正确否则会重复或丢失。
8. 语音（可选）：返回 JSON + `scp` 可达的远端绝对路径，不是二进制流。

**4 秒内**她应主动冒泡念出来。
